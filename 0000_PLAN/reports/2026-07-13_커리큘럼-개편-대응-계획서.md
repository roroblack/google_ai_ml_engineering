### W8·W9 — 학습 확장 (Section 3, **21% 최대 배점**) · Keras deprecated → 문서 + codelab으로 대체

**Keras 코스 방침: 중단·스킵.**
근거 — 시험 가이드 원문 *"The exam does not directly assess coding skills."* Section 3.2가 요구하는 건 Keras 코딩이 아니라 **"custom training / Kubeflow on GKE / AutoML / Tabular Workflows 중 무엇을 고를지"** 와 **HPT·분산전략·fine-tuning 시점 판단**입니다.
→ 대신 **`17` Production Machine Learning Systems**(16h, 현 카탈로그 유지)를 축으로 삼고, 아래 codelab으로 손을 씁니다.

**해야 할 것**
1. **같은 학습 코드를 3경로로 제출**: ① prebuilt container + `gs://` ② custom container(Artifact Registry push) ③ managed dataset. 각 경로의 IAM(특히 **Custom Code Service Agent**) 메모.
2. **일부러 실패시키기**: 큰 batch size로 **OOM** 유발 → error code 확인 → machine type 상향으로 해결. spot VM으로 stockout·재시도 관찰. (트러블슈팅 문항 = "증상→원인" 매핑)
3. **HPT 실습**: `hypertune`으로 metric 보고 → `parameterSpec` scaling(LINEAR vs LOG) → trial 수와 `maxParallelTrials`를 바꿔 **Bayesian이 왜 병렬성 높이면 손해인지** 체감. **Vizier와 HPT 차이**(Vizier=학습잡 없이 쓰는 범용 black-box optimizer) 한 줄 정리.
4. **Gemini SFT 1회 완주**: JSONL 준비 → LoRA adapter size → ROUGE로 base vs tuned 비교. **"언제 tuning을 고려하나"**(prompt·RAG로 안 될 때, style/format/domain 모방 필요할 때) 자기 문장으로.
5. **분산학습**: `MirroredStrategy`(1머신 N GPU) → `MultiWorkerMirroredStrategy`(N머신) 직접 실행. **Reduction Server**를 켜보고 **적용 조건**(GPU multi-host + data-parallel + TF/PyTorch) 확인 — 이 제약이 함정 문제.
6. **CPU/GPU/TPU 선택 기준 암기**: TPU=matrix 연산 지배적·초대형 학습 / GPU=custom op 많음·중대형 / CPU=프로토타이핑·단순 모델. **TPU 부적합 = frequent branching, high-precision arithmetic.**

1. **KFP SDK v2로 3-step 파이프라인 직접 작성**: `@component` → `@dsl.pipeline` → `compile()` → `PipelineJob.submit()`. `Artifact`/`Dataset`/`Model` 타입으로 **컴포넌트 간 artifact 전달**을 반드시 손으로.
2. **GCPC 사전제작 컴포넌트 1개 섞기**(`ModelUploadOp`/`EndpointCreateOp`/`ModelDeployOp`) → "custom vs template" 차이 체감.
3. **같은 워크로드를 Airflow DAG로도** 오케스트레이션 → **"언제 Pipelines vs 언제 Composer"** 기준 정리 (출제 포인트).
4. **Ray on Agent Platform 클러스터 1회 생성·삭제** (비용 주의, 오래 켜두지 말 것).
5. **캐싱 실험**: 같은 파이프라인 2회 연속 실행 → 2회차 "Cached" 확인 → 코드 한 줄 바꿔 **캐시가 깨지는 조건** 확인. `enable_caching=False`를 run/task 레벨로 각각.
6. **재학습 트리거 3종 표로**: ① 스케줄 → Scheduler API ② 데이터 도착 → Pub/Sub + Cloud Run ③ 성능 저하 → Model Monitoring alert.
7. **Cloud Build trigger 실제로 붙이기**: GitHub push → `cloudbuild.yaml` → 파이프라인 컴파일·업로드·제출.
8. **MLOps level 0/1/2 백지 재현**: level 1 = **파이프라인** 자동화(산출물이 model이 아니라 pipeline), level 2 = **파이프라인 코드 자체의 CI/CD**. 이 뉘앙스가 오답 유도 포인트.
